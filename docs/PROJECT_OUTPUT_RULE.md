# Project Output Rule

## Purpose

This repository records the Systemic Functional Linguistics (SFL) meaning-model build as a reproducible engineering and research programme. Project communication, implementation notes, experiment records, and generated working outputs begin and end with substantive additive content to that programme.

## Rule

Every project output must begin and end with material that directly advances at least one of the following:

- a verified source, repository, data, model, training, test, or experiment fact;
- a concrete implementation decision or a resolved design boundary;
- executable code, configuration, documentation, or an exact data/model/loss contract;
- a versioned experiment result, checkpoint lineage, evaluation result, issue resolution, or commit-level change.

## Exclusions

The rule excludes progress narration without evidence, generic assurances, repeated plans, placeholders, fabricated interfaces, and claims of background work that have not occurred.

## SFL Build Application

For the SFL meaning-state model, substantive output preserves the distinction between structured SFL meaning states and their current nine-dimensional numerical projection. The initial empirical route remains:

    empirical UAM trajectories
    -> 3 x 3 / 9D meaning-state projection
    -> meaning-state autoregressive transition
    -> trajectory loss
    -> randomly initialised checkpoint

Read aloud: “An empirical meaning trajectory is projected into a nine-dimensional numerical state; the model predicts the next meaning state; the trajectory loss compares that prediction with the observed next state.”

## Completion Test

Before sending or recording an output, confirm that its first and final substantive statements each add a verifiable project fact, implementation artifact, decision, result, or directly executable next operation.
